## 1. Primary Dataset: Synthetic Virtual Sensor Network

Due to hardware constraints (single laptop, no external IoT devices), real-time sensor data is generated by an autonomous virtual IoT sensor simulator (`simulator/`).

### Generator Characteristics:
- **Language & Libraries:** Python 3.13, NumPy (`numpy.random.default_rng`), PyYAML.
- **Controlled Rates:** 10, 50, 100, 500, 1,000, and 5,000 events/second.
- **Reproducibility:** Seeded pseudo-random number generator (`seed=42`).
- **Simulated Hardware Realism:**
  - Battery decay modeling (100% down to low battery threshold).
  - RF signal strength variance (-30 dBm to -95 dBm).
  - Microsecond ingestion jitter (10ms to 500ms network delay).
  - Hardware packet duplication (2%).
  - Network delay / clock desynchronization (3% late events up to 180s).
  - Corrupted coordinate payloads (1% out-of-range latitude/longitude).

## 3. Historical Dataset: City of Melbourne 2019 On-Street Parking

For historical replay experiments, the pipeline supports the City of Melbourne 2019 On-Street Parking Bay sensor dataset:
- **Source Portal:** `https://data.melbourne.vic.gov.au/`
- **License:** Creative Commons Attribution 4.0 International (CC BY 4.0).
- **Format:** CSV records containing `bay_id`, `arrival_time`, `departure_time`, `duration_seconds`.
- **Replay Engine:** `ingestion/historical_replay.py` converts records to canonical schema v1.0, tags them as `"source": "HISTORICAL_REPLAY"` and `"city": "Melbourne"`, and feeds them into Kafka.
- **Academic Separation:** Replay data is never conflated with Bengaluru live telemetry.
